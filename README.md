# 교육 운영 통합관리 앱 (excelflow)

교육 운영 담당자와 교육생(내부 직원)이 **교육생 선정부터 불참·충원까지의 변경 사항을 한곳에서 관리·공유**하는 웹 앱입니다. 흩어진 엑셀·메일·카톡 대신 하나의 명단과 하나의 안내 페이지를 같이 봅니다.

> ⚠ **실습용 프로젝트입니다.** 화면과 저장 데이터는 모두 **가짜 명단**이며, 로그인은 실습용 공통 비밀번호를 씁니다. 실제 직원 정보나 사내 계정을 넣지 마세요. 배포본은 Supabase에 저장하지만 실습용이라 실제 정보는 넣지 마세요(아래 "알려진 한계" 참고).

## 무엇을 하나요

**담당자 화면 (`/` 에서 비밀번호로 로그인)**
- 과정 정보(일정·장소·안내문·회신 기한) 입력 — 저장하면 "최종 수정 일시"가 교육생 화면에 표시
- 신청자 엑셀(`.xlsx`, 최대 1,000행) 업로드: 중복 사번 처리, 사번 6자리 검사, 앞자리 0 보존
- 1차 선별(체크하면 바로 선정) → 2차 랜덤 추첨(정원·대기 인원, 재추첨, 기록은 수정 불가)
- 회신 현황(참석·불참·노트북·룸메이트·미회신)과 담당자 대리 입력
- 불참·직접 제외 → 대기 순번대로 충원 확정(정원 초과 경고, 개별 회신 기한), 수기 추가
- 충원이 필요한 자리 알림(상단 배너·메뉴 배지, 30초마다 자동 갱신)
- 모든 변경의 이력(일시·변경 전·변경 후) 조회, 최종 명단 엑셀 내려받기(사번은 텍스트 서식)

**교육생 화면 (`/trainee`, 모든 교육생이 같은 주소)**
- 사번 6자리 + 비밀번호로 로그인(5번 연속 틀리면 15분 잠금, 실패 사유는 항상 같은 문구)
- 내 선정 결과와 교육 안내 확인(본인 정보만 표시), 회신 기한까지 남은 시간
- 참석/불참(사유 10~300자), 노트북 지참, 룸메이트(이름·부서 직접 입력) 회신 제출·수정
- 휴대폰 화면 폭(375px)에서 가로 스크롤 없이 사용

## 기술

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · exceljs · zod · Vitest

```text
src/domain   화면·저장소를 모르는 순수 규칙(상태 전환, 정원, 추첨, 회신 검사 …)
src/lib      로그인, 이력 기록, 충원·수기 추가 등 기능
src/store    저장 창구(한곳에 모아 두어 나중에 DB로 교체하기 쉽게)
src/app      담당자·교육생 화면과 서버 처리
tests        핵심 규칙 자동 검사
```

## 직접 실행해 보기

```bash
npm install
# 프로젝트 폴더에 .env 파일을 만들어 아래 "환경 변수"를 채웁니다 (실제 값은 저장소에 올리지 않습니다)
npm run dev            # http://localhost:3000
```

가짜 비밀번호로 바로 확인하려면:

```bash
npm run dev:test       # http://localhost:3100  (담당자 test-admin-pass / 교육생 test-trainee-pass)
```

`fixtures/applicants-30.xlsx`가 가짜 신청자 30행(고유 28명, 중복 사번 2행, 앞자리 0 사번 5개)입니다.

```bash
npm test               # 핵심 규칙 자동 검사
npm run lint
npm run build
```

## 환경 변수

| 이름 | 용도 |
|------|------|
| `ADMIN_PASSWORD` | 담당자 로그인 비밀번호 |
| `TRAINEE_TEST_PASSWORD` | 교육생 실습용 공통 비밀번호 |
| `SESSION_SECRET` | 로그인 쿠키 서명 키(32자 이상 무작위 값) |
| `DATABASE_URL` | (배포용) Supabase(Postgres) 접속 정보. 있고 `DATA_FILE`이 없으면 DB에 저장한다 |
| `DATA_FILE` | (개발용, 선택) 저장 파일 위치. 있으면 항상 파일에 저장한다(`npm run dev:test`가 사용) |

실제 값은 `.env`(저장소에 올리지 않음) 또는 배포 서비스의 환경 변수에만 둡니다.

## 여러 과정 운영 · DB 이전 (처음 한 번)

과정이 하나뿐이던 예전 데이터(`app_state` 표)를 "첫 번째 과정"으로 옮겨야 새 코드가 동작합니다. **새 코드를 배포하기 전에** 먼저 실행하세요.

```bash
node scripts/migrate-multi-course.mjs
```

미리 보기입니다: 모든 단계를 실행해 검증한 뒤 되돌리며 DB에 아무것도 남기지 않습니다. 문제가 없으면 실제로 적용합니다.

```bash
node scripts/migrate-multi-course.mjs --apply
```

새 표 `course_state`·`login_attempts`를 만들고, 예전 표를 `app_state_backup_<날짜>`로 백업하며, 예전 데이터를 한 글자도 바꾸지 않고 첫 번째 과정으로 복사한 뒤 원본과 같은지 검증합니다. 예전 `app_state` 표는 지우지 않고 남겨 두므로, 문제가 생기면 이전 버전 코드로 되돌릴 수 있습니다. 이미 이전했으면 아무것도 하지 않습니다.

개발용 파일 저장은 `data/db.json`이 있으면 처음 실행할 때 자동으로 첫 번째 과정으로 옮기고 원본을 `db.json.v1.bak`으로 남깁니다.

## 알려진 한계 (공개 전 점검 결과 — `CHECK.md` 참고)

- **저장:** 배포본은 Supabase(Postgres)에 저장합니다(`src/store/pgCatalog.ts`·`pgStore.ts`: 과정마다 표 `course_state`의 한 행에 JSON으로 저장하고 그 행에 대한 잠금 거래로 동시 요청을 보호, 로그인 실패 기록은 사번별 표 `login_attempts`). 내 컴퓨터 개발·확인용은 `data/courses/<번호>.json` 파일입니다. 선택은 `src/store/index.ts`의 `getCatalog()` 한 곳에서 합니다. 명단이 아주 커지면 표를 나누는 설계로 옮겨야 합니다. 불참 사유는 평문으로 저장되므로 실제 운영 전에 보관·암호화 정책이 필요합니다.
- 교육생 로그인은 **공통 비밀번호**라서 사번을 아는 사람은 다른 교육생으로 로그인할 수 있습니다. 실제 직원 데이터를 쓰기 전에 사람마다 다른 인증으로 바꿔야 합니다.
- 담당자 로그인 시도 제한은 서버 메모리 기준이라 서버가 여러 대로 나뉘면 서버마다 따로 셉니다(공용 저장으로 옮기는 것은 다음 작업).
- 사내 시스템 연동, SSO, 메일·문자·카톡 자동 발송은 이번 범위에 포함하지 않았습니다. (여러 과정 운영은 2026-11-12에 범위에 포함했습니다.)
